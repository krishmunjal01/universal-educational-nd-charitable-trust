# Aashray: Small Actions, Real Change

Build a Premium, Editorial-Style NGO Website — Aashray

1. Project Overview

Build a complete, modern, premium, production-oriented NGO website for Aashray, inspired by the attached website design reference.

The NGO website should communicate compassion, trust, community development, and sustainable change. It should look like a professionally art-directed nonprofit website, not a generic template or a typical corporate landing page.

Primary tagline: Small Actions. Real Change.

Supporting message: Working together to build a fairer, healthier, and more sustainable future for everyone.

Use the attached reference image as the primary visual direction. Study its typography, photography, page layouts, color palette, spacing, section hierarchy, navigation, and decorative details before implementation.

Do not reproduce the composite image as a flat screenshot. Recreate its individual pages as fully responsive, functional website pages.

2. Design Direction and Visual Identity

Overall aesthetic

The design must feel:

Premium, minimal, warm, elegant, and trustworthy.

Editorial and photography-driven.

Human-centered and emotionally engaging.

Sophisticated without appearing luxurious or commercial.

Modern, with subtle natural and organic design elements.

Use generous whitespace, asymmetrical editorial layouts, refined typography, beautiful imagery, restrained decoration, and consistent spacing.

Avoid generic SaaS layouts, oversized rounded cards, excessive gradients, neon colors, cartoon illustrations, excessive 3D objects, and flashy animations.

Color palette

Establish a consistent design system using these colors:

Forest green: #123D32

Deep green: #0B2F27

Warm ivory: #F7F4EC

Soft beige: #EAE4D7

Muted olive: #879077

Charcoal: #262A25

Secondary text: #666A60

White: #FFFFFF

Use ivory as the primary page background, forest green for important buttons and accents, and deep green for selected full-width storytelling sections and the footer.

Avoid making every section the same color. Alternate light backgrounds, photographs, and dark-green sections to create a natural visual rhythm.

Typography

Use an elegant editorial serif typeface such as Cormorant Garamond or DM Serif Display for major headlines and storytelling statements.

Use Inter or a similar clean sans-serif for navigation, body copy, statistics, labels, forms, and buttons.

Headlines should be expressive, readable, and moderately sized. Use strong typography and line breaks rather than oversized text everywhere.

Photography

Use authentic, high-quality documentary-style photography depicting Indian communities, rural children, education, healthcare, farming, environmental restoration, and volunteers working alongside communities.

Prefer natural lighting, warm earthy tones, genuine human expressions, and images that communicate dignity and hope.

Use large photographs with carefully cropped subjects, consistent image treatments, and occasional overlapping organic decorative elements.

Never use cartoon people, artificial-looking illustrations, or unrelated corporate stock photography. Do not fabricate identifiable beneficiaries or claim that stock photographs depict actual NGO beneficiaries.

If actual organizational photographs are unavailable, use suitable placeholder imagery that can be replaced later.

12. Interaction and Animation

Smooth scrolling for same-page links.

Small image-scale transitions on hover.

Understated button hover states.

Smooth mobile navigation.

Accessible accordion or carousel interactions where appropriate.

Do not animate every element or delay important content behind loading effects.

13. Responsive Design

The site must work beautifully on desktop, tablet, and mobile.

Desktop:

Preserve the spacious editorial composition.

Use generous horizontal margins.

Use two-column layouts and large photography where appropriate.

Tablet:

Reduce spacing proportionally.

Prevent text and images from becoming cramped.

Adapt two-column layouts where necessary.

Mobile:

Stack sections vertically.

Keep headlines readable.

Use full-width or comfortably sized CTAs.

Make forms easy to complete.

Ensure statistics, images, and navigation fit the viewport.

Avoid horizontal overflow and tiny text.

Keep important content visible without excessive scrolling.

Do not simply shrink the desktop layout. Design a deliberate mobile experience.

14. Technical Requirements

Use the existing project stack and conventions. Prefer React, TypeScript, Tailwind CSS, and reusable components where supported.

Build a maintainable component structure, including:

Header and mobile navigation.

Footer.

Hero sections.

Impact statistics.

Program sections.

Story sections.

CTA sections.

Donation form.

Volunteer and contact forms.

Use Lucide icons or similarly restrained line icons.

Store repeatable content, program descriptions, statistics, and team information in centralized editable data rather than duplicating hard-coded content across components.

Use semantic HTML, accessible form labels, suitable color contrast, responsive images, meaningful image alt text, and appropriate page metadata.

Avoid unnecessary dependencies and oversized animation libraries.

If Supabase or another backend is available, use it for the relevant data and form integrations only after configuring the necessary schema, access controls, and environment variables. Do not assume an external service is connected.

Ensure there are no broken routes, dead buttons, non-functional forms, missing images, console errors, or horizontal overflow.

15. Performance, Accessibility, and SEO

Optimize image sizes and use responsive image loading.

Lazy-load below-the-fold imagery where appropriate.

Avoid unnecessary layout shifts.

Use descriptive page titles and meta descriptions.

Implement logical heading hierarchy.

Ensure keyboard navigation and visible focus states.

Use accessible contrast and reduced-motion support.

Provide meaningful alt text for informative images and empty alt text for purely decorative images.

Add appropriate social-sharing metadata.

Do not add fake reviews, fabricated statistics, or misleading structured data.

16. Content and Trust Requirements

Treat all organizational facts as data that must be verified.

Do not invent:

NGO registration or tax-exemption status.

Official contact details.

Founders, staff, or team identities.

Beneficiary testimonials.

Donations received.

Project achievements.

Verified impact metrics.

Partnerships, awards, or certifications.

Where real information is missing, use clearly labeled editable placeholders and make them easy to replace.

The final website should communicate trust through transparent content, thoughtful design, and clear calls to action.

17. Final Implementation Instructions

Before implementation, inspect the attached reference and establish the design system, reusable components, page structure, and responsive layout strategy.

Build the website as a cohesive multi-page experience, not a single-page mockup.

Prioritize the homepage first, then implement all remaining pages using the same design system.

Do not simplify the design into a generic template. Preserve the reference's distinctive combination of warm ivory backgrounds, forest-green accents, elegant serif typography, documentary photography, minimal cards, editorial layouts, and full-width storytelling sections.

Make the website visually polished, functional, accessible, and easy to maintain.

Final acceptance criteria:

All seven pages exist and are navigable.

The desktop design closely follows the reference's visual direction.

Mobile layouts are deliberately designed and responsive.

All links, menus, buttons, and local interactions work.

Forms validate correctly and clearly communicate their actual submission status.

The donation flow is ready for secure payment-provider integration without faking transactions.

All organizational facts are verified or clearly marked as placeholders.

The site is consistent, fast, accessible, and production-oriented.

Start building the actual website now. Do not stop at a design description or a static wireframe.
